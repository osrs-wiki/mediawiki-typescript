# Action API modules

This directory is populated across two phases (see `docs/plans/api/plan.md`):

- `generated/` — codegen output from `action=paraminfo` (typed request params for every module).
  Generated by `packages/api/codegen/` via `npm run codegen -- --wiki <url> --out src/action/generated`.
  Re-run after a MediaWiki upgrade to pick up new/changed modules; the output is committed, not
  regenerated at consumer install/build time. 270 modules as of the `www.mediawiki.org` run.
- `core/` — hand-authored precise response types + ergonomic wrappers for the curated
  high-value modules: `edit`, `parsePage`, `deletePage`, `movePage`, `compare`, `opensearch`,
  `upload`, `tokens`, `siteinfo`, and `query/` (`query`, `queryRevisionContent`, and the
  `allPages`/`search`/`categoryMembers`/`backlinks` list helpers). Content-bearing modules use
  the `../content` bridge helpers.
- `ActionApiClient.ts` — facade binding every `core/` function to one `MediaWikiClient` instance
  (`new ActionApiClient(client)` → `actionApi.edit(...)`, `actionApi.query.query(...)`, etc.).

`manifest.test.ts` is a coverage guardrail asserting the crawl found a substantial module count
and includes every module the `core/` tier depends on.

For anything outside the curated `core/` set, call `client.call(action, params)` directly using
the matching generated `*Params` type from `generated/`.
